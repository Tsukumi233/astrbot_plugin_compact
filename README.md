# 手动压缩上下文 / Compact

在当前聊天发送 `/compact`，立即调用 AstrBot 内置的 LLM 摘要压缩器，无需等到自动压缩阈值。不修改核心，不接管日常上下文管理，也不关闭自动压缩。

## 安装与要求

AstrBot **4.29.x**、内置 `local` Agent，以及可用的聊天/压缩模型。插件没有额外 Python 依赖。使用了核心压缩和会话锁接口，因此暂时限制到经过验证的版本系列。

WebUI → 插件 → 安装插件 → 从链接安装：

```
https://github.com/Tsukumi233/astrbot_plugin_compact
```

适用于 AstrBot 命令支持的聊天适配器；没有平台专属调用。权限与内置 `/reset`、`/new` 一致：共享群会话默认仅 AstrBot 管理员可用，私聊及核心标记为隔离的个人会话允许普通用户；QQ 群管理员身份本身不等于 AstrBot 管理员。实际权限可由指令管理设置调整。唤醒方式沿用机器人配置，必要时 @机器人再发送 `/compact`。

## 行为

- 接受 `/compact` 后立即回复“开始压缩”，再等待会话锁和模型处理，结束后另行回复结果。重复请求仍只提示已有任务；未通过权限检查的请求不会发送开始提示。
- 读取当前会话路由对应的 `agent_runner.config.compression`。
- 优先使用配置的压缩 Provider，留空使用当前会话聊天 Provider；沿用压缩提示词及近期保留比例。
- 调用内置压缩器，生成摘要并保留近期完整轮次及其 checkpoint；成功后通过 ConversationManager 保存。
- 与普通内置 Agent 共用会话锁，等待正在执行的回复完成；重复命令会提示已有任务。
- 180 秒超时包含等待会话锁与模型请求。模型失败、空摘要、结果不更短时不写回，也不回退为删除旧消息。
- 写入前复核会话 ID 和原始历史，发现切换、清空或变更就放弃结果。
- 重置过时的上下文 token_usage 缓存；回复中的 Token 是估算值，不是计费统计。

压缩会调用配置的模型并可能产生费用，也会丢失部分旧对话细节。插件不建立额外历史备份或数据库。第三方 Agent（Dify/Coze 等）不受支持。

并发保护适用于单进程内置 Agent。其他插件若绕过核心会话锁写历史，或多个进程共享同一数据库，无法保证最后检查与写入之间的原子比较；请避免这些用法。

## 开发验证

在 AstrBot 4.29.x 的 Python 环境中运行：

```bash
python -m unittest discover -s tests -v
```

测试使用合成历史和假的 Provider，不读取真实聊天、不调用付费模型。
